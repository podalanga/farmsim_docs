# Understand the experiment files

!!! info "Tutorial overview"
    - **Goal**: read the four YAML files of the AmphiBot example, and change
      the start position, the arena and the gait.
    - **Level**: beginner
    - **Time**: 30 minutes
    - **Prerequisites**: [Your first simulation](first-simulation.md)

## Background

`examples/amphibot/` holds:

```text
examples/amphibot/
├── experiment_config.yaml        # Entry point: lists the files below
├── experiment_config_wave.yaml   # Same, with the custom controller
├── simulation_config.yaml        # Time, physics, viewer, loggers
├── arena_config.yaml             # Ground and water
├── animat_config.yaml            # The robot (generated)
├── animat_config_wave.yaml       # The robot with the custom controller (generated)
├── generate_config.py            # Generates the two animat files
├── models/                       # SDF files: robot, arena, water
├── controller/                   # The custom controller (tutorial 4)
└── run_sim.py
```

Each YAML file is loaded into an option class, named in
`experiment_config.yaml`. Every key is documented in the
[configuration reference](../reference/env/configuration-reference.md).

## Step 1: The experiment file

```yaml
# examples/amphibot/experiment_config.yaml
simulation: simulation_config.yaml
animats:
- animat_config.yaml
arenas:
- arena_config.yaml
loaders:
  simulation_options: farms_core.simulation.options.SimulationOptions
  animats_options:
  - farms_amphibious.model.options.AmphibiousOptions
  arenas_options:
  - farms_amphibious.model.options.AmphibiousArenaOptions
  experiment_data: farms_amphibious.data.data.AmphibiousExperimentData
  animats_data:
  - farms_amphibious.data.data.AmphibiousData
```

- `simulation`, `animats`, `arenas`: the other files, relative to this one.
  `animats` and `arenas` are lists: a scene can hold several robots.
- `loaders`: the classes that read each file and hold the recorded data.
  The `farms_amphibious` classes add the CPG network to the generic
  `farms_core` ones; the built-in CPG controller needs them.

## Step 2: The simulation file

```yaml
# examples/amphibot/simulation_config.yaml (shortened)
runtime:
  n_iterations: 10001   # Number of steps
  buffer_size: 10001    # Steps kept in memory and logged
  headless: false       # true: no viewer
  show_progress: true
physics:
  timestep: 0.001       # [s] 10001 steps of 1 ms: 10 s
  gravity: [0, 0, -9.81]
  num_sub_steps: 1
  cb_sub_steps: 2
mujoco:
  solver: CG
  integrator: implicitfast
extensions:             # Run at every step, in this order
- loader: farms_core.simulation.extensions.ExperimentLogger
  config:
    log_path: Output
- loader: farms_core.simulation.extensions.ExperimentOptionsLogger
  config:
    log_path: Output
- loader: farms_mujoco.simulation.extensions.MjcfSaver
  config:
    path: Output/simulation_mjcf.xml
- loader: farms_mujoco.simulation.extensions.CameraFollower
  config:
    animat_id: 0
    distance: 1.5
    azimuth: 30
    elevation: -20
```

**Try it**: double the duration with `n_iterations: 20001` and
`buffer_size: 20001`. AmphiBot swims further into the pool.

## Step 3: The arena file

```yaml
# examples/amphibot/arena_config.yaml
sdf: models/arena_ramp.sdf      # Land, ramp and pool floor
spawn:
  pose: [0, 0, 0, 0, 0, 0]
water:
  sdf: models/water.sdf         # Water volume, visual only
  height: 0                     # [m] Water surface
  density: 1000.0               # [kg/m^3]
  buoyancy: true
  drag: true
  cob_method: exact             # Centre of buoyancy method
ground_height: 0
```

The arena SDF is a static model, like the robot's: boxes for the land
(top at z = 0.05 m), the 7.8 degree ramp and the pool floor. The water is
not a body: everything below `water.height` gets buoyancy and drag from
`farms_mujoco`. [Tutorial 5](swimming.md) covers the water options.

**Try it**: set `height: -0.3`. The pool is half empty, AmphiBot reaches
the water further down the ramp.

## Step 4: The animat file

The animat file describes the robot. It is long (about 1700 lines)
because it lists every link, joint, sensor, motor, oscillator and coupling,
so it is generated by `generate_config.py` from a few parameters. Its main
blocks:

| Block | Content |
|---|---|
| `sdf`, `spawn` | The robot model and where it starts |
| `morphology.links` | Per link: contact `friction`, `fluid_interaction`, `drag_coefficients` |
| `morphology.joints` | Per joint: initial state, limits, stiffness, damping |
| `control.sensors` | Which links, joints and contacts are recorded |
| `control.motors` | Per joint: control type, torque limit, gains, equation |
| `control.network` | The CPG: drives, oscillators, couplings |
| `control.muscles` | Which oscillators drive which joint |
| `extensions` | The controller and the water forces |

The start of the file:

```yaml
# check-docs: skip
sdf: models/amphibot.sdf
spawn:
  pose: [-1.0, 0, 0.075, 0, 0, 0]   # [x, y, z, roll, pitch, yaw], on land
morphology:
  links:
  - name: head
    collisions: true
    friction: [0.5, 0, 0]
    fluid_interaction: true
    drag_coefficients:
    - [-0.25, -1.5, -1.8]           # Linear drag along x, y, z (link frame)
    - [0, 0, 0]                     # Angular drag
```

One motor:

```yaml
# check-docs: skip
control:
  motors:
  - joint_name: joint1
    control_types: [position]
    limits_torque: [-2.0, 2.0]      # [Nm]
    gains: [1.0, 0.01, 0]           # Position and velocity gains
    equation: position_muscle       # Target from the two oscillators
```

The CPG has two oscillators per joint (left and right), 14 in total.
Each has an intrinsic frequency and amplitude that grow with the drive:

```yaml
# check-docs: skip
control:
  network:
    drives:
    - name: drive_body_0_L
      initial_value: 4.0
    oscillators:
    - name: osc_body_0_L
      frequency_gain: 1.5708        # [rad/s] per drive unit: 2 pi rad/s (1 Hz) at drive 4
      amplitude_gain: 0.15
    osc2osc:
    - in: osc_body_1_L              # Each oscillator pulls its neighbours
      out: osc_body_0_L
      weight: 30.0
      phase_bias: 0.718             # 2 pi x 0.8 waves / 7 joints
```

The [CPG control architecture](../explanation/cpg-architecture.md) page
explains the equations.

## Step 5: Change the robot through the generator

Edit `generate_config.py` rather than the generated files. For example,
a faster swimming wave:

```python
FREQUENCY = 1.5  # [Hz] at DRIVE
WAVES = 1.0      # Number of waves along the body
```

Then regenerate and run:

```bash
python generate_config.py
python run_sim.py --experiment_config experiment_config.yaml
```

To start in the water instead of on land, change `spawn_position` in
`generate_config.py` to `[4.5, 0, 0.0]`.

## Summary

- `experiment_config.yaml` lists the simulation, animat and arena files,
  and the classes that load them.
- `simulation_config.yaml` sets time, physics and the extensions that run
  at every step (loggers, camera).
- `arena_config.yaml` places the ground model and the water surface.
- `animat_config.yaml` describes the robot, its motors and its controller.
  For the amphibious CPG it is generated from a few parameters.
